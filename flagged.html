F-23 — Privacy: tenant initials remain in this repository's git history

Found and fixed in the published files. An earlier session quoted the six supplied tenant initial pairs inside COORDINATION.md while reviewing a different pull request. Because GitHub Pages serves the repository root, that Markdown file was publicly retrievable at the site URL. The initials have now been redacted from the live file, and the automated privacy sweep was extended to cover README.md and COORDINATION.md as well as every HTML page, so this cannot recur undetected.

What is still outstanding. This repository is public, and redaction only changes the current version. The earlier commits still contain the initials and remain reachable through the repository's history. No page on this site displays them, and no current file contains them, but history is a separate exposure.

Options for the owner to decide. (1) Make the repository private — GitHub Pages access control depends on the plan, so check the effect on the live site first. (2) Rewrite history to remove the string and force-push, which is destructive and would discard other sessions' commit identities, so it was deliberately not done automatically. (3) Accept the exposure on the basis that initials alone are weak identifiers. This is the owner's call, not an automated one.
